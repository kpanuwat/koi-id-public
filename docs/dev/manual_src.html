1สรุปสำหรับนักพัฒนาDeveloper summary

1.1 ระบบนี้คืออะไร What it is

Koi ID เป็น PWA ที่นับปลาคอย (koi) จากภาพถ่าย วิดีโอไฟล์ หรือกล้องสดของโทรศัพท์ ตัวตรวจจับวัตถุคือ YOLOX-tiny ที่รันบนเครื่องผ่าน ONNX Runtime Web บน WebGPU และมี wasm เป็นตัวสำรอง โค้ดเป็น ES module ธรรมดาใน app/ ไม่มีตัวรวมโค้ด (bundler) ฝั่งเซิร์ฟเวอร์ใช้ Cloudflare Pages Functions และฐานข้อมูล D1

ตั้งแต่ v0.064 โหมดนับเป็นค่าเริ่มต้น จึงไม่ต้องใส่ ?count=1 แล้ว โหมดเต็มซึ่งมีการระบุตัวปลาและการซิงก์คลังเปิดด้วย ?count=0 โหมดนับเป็นเส้นทางเดียวที่ได้หลักฐานว่ามั่นคงบน iPhone จึงเป็นจุดเริ่มของการพัฒนาต่อ

1.3 เริ่มต้นใน 10 นาที Start in 10 minutes

  1. อ่าน HANDOFF.md ส่วน CHECKPOINT และไดเรกทอรี docs/claude/ (ทิศทางของเจ้าของระบบ)
  2. Clone รีโพจาก GitHub เข้าไปในโฟลเดอร์รีโพ แล้วรัน ./scripts/fetch_artifacts.sh เพื่อดึงไฟล์ใหญ่ราว 580 MB จาก GitHub Release
  3. ติดตั้ง Node.js (v22 ขึ้นไป) และ Python 3.12 สำหรับโฟลเดอร์ train/ ตามขั้นตอนใน SETUP.md
  4. รันเซิร์ฟเวอร์ local: cd app && npx --yes http-server@14.1.1 -p 8766 -a 127.0.0.1 -c-1 -s
  5. เปิด http://127.0.0.1:8766/ (โหมดนับ) และ http://127.0.0.1:8766/?count=0 (โหมดเต็ม) บน Chrome เดสก์ท็อปก่อนเสมอ
  6. ตรวจไวยากรณ์ก่อนแก้โมดูล: คัดลอกโมดูลเป็นไฟล์ .mjs ในโฟลเดอร์ชั่วคราว แล้วรัน node --check (ดูหัวข้อ 11)
  7. ทดสอบรอบนับกับภาพนิ่ง: train/.venv/bin/python -I pending/yolox/count_check.py http://127.0.0.1:8766 <ภาพใต้ app/>
  8. ถ้าแก้การตรวจจับ การติดตาม หรือการนับ ให้รัน eval ก่อนและหลังแก้ (หัวข้อ 10)
ห้ามส่งคำขอเขียนหรือข้อมูลทดสอบไปยัง production และห้ามรัน wrangler แบบ --remote เพื่อทดสอบ ให้ใช้ wrangler pages dev แบบ local เท่านั้น

2.2 หลักการออกแบบที่ตัดสินแล้ว Decided design rules

  • คงเป็น PWA ไม่ทำ native app และไม่ใช้ App Store ตามทิศทางของเจ้าของระบบ
  • การตรวจจับและการนับทำบนเครื่อง งานเบื้องหลังช้าได้ แต่การแสดงผลและการติดตามต้องลื่น
  • ความแม่นยำมาจากภาพความละเอียดเต็ม ไม่ย่อภาพเพื่อการคำนวณ (การแสดงผลแยกจากกัน)
  • ไม่มีค่าใช้จ่ายใบอนุญาต จึงใช้ YOLOX (Apache-2.0) แทน Ultralytics (AGPL) และใช้ Cloudflare free tier กับ Google Colab
  • การอนุมานทีละครั้ง: ONNX Runtime Web ไม่รันสองการอนุมานพร้อมกัน ทุกการเรียกเข้าคิวใน engine.js
  • การตั้งค่าอัตโนมัติ: บ่อมาจาก GPS ตอนเปิดกล้อง ไม่มีปุ่มซิงก์ให้ผู้ใช้ตั้งเอง
  • คลังปลาบนเซิร์ฟเวอร์เป็นแหล่งความจริงเดียวของหมายเลขและชื่อปลา หมายเลขห้ามนำกลับมาใช้ใหม่
  • กติกาชื่อปลา: ไม่ซ้ำ ไม่มีตัวเลข ยาวไม่เกิน 10 code point ปลาที่ยังไม่มีชื่อแสดงรหัส 2 หลัก (hex)
  • พิกัดบ่อเก็บทศนิยม 3 ตำแหน่งเพื่อความเป็นส่วนตัว และไม่ใช้ข้อมูลภูมิศาสตร์จาก Google หรือ OSM
  • นับเฉพาะปลาในน้ำ และไม่แก้ไขพิกเซลของภาพต้นฉบับ

ที่มา: บันทึก Owner decisions ใน HANDOFF.md (ณ 26 ต.ค. 2026) ข้อใดยังใช้อยู่ให้ยืนยันกับเจ้าของระบบก่อนเปลี่ยนโค้ด

2.3 เส้นทางข้อมูล Data paths

  • นับในเครื่อง (count path): เฟรม (ImageBitmap) ไปยังหน้าเว็บ แล้วไปยังเวิร์กเกอร์ ผ่าน YOLOX แล้วได้กล่องและจำนวนกลับมาวาดบนจอ โหมดนับไม่ดึงหรือส่งคลังปลา แต่ยังลงทะเบียนอุปกรณ์และส่ง log
  • บ่อและคลังปลา (sync path): หน้าเว็บเรียก /api/* ด้วยโทเคนอุปกรณ์ แล้วเขียนลง D1 ใช้เฉพาะโหมดเต็ม
  • log (field diagnostics): report() ส่ง POST /api/log เข้าตาราง logs อ่านได้ด้วย SQL (หัวข้อ 9.4)

4วงจรนับต่อเนื่องContinuous count loop

  3. เรียก photoRun(bitmap, true) โดยโอนความเป็นเจ้าของ ImageBitmap ด้วย transferToImageBitmap() ทำให้ canvas ว่างโดยไม่ต้องคัดลอกซ้ำ
  4. ใน photoRun ถ้ามีรอบอื่นทำงานอยู่ (photoBusy) จะคืนค่าทันที ถ้าด้านยาวเกิน 1920 px จะย่อด้วย scaledBitmap วาดลง canvas #view แล้วทำสำเนา nb เป็นพื้นหลังของผลรอบ
  5. engine.detect() ส่ง bitmap ไปเวิร์กเกอร์ด้วย transfer list และคิวการเรียกทำให้มีการอนุมานทีละครั้ง
  6. ในเวิร์กเกอร์ pipeline.detect วาดภาพลง OffscreenCanvas ที่ใช้ซ้ำ ปิด bitmap แล้วเรียก detectYolox: ย่อแบบ letterbox เป็น 320 x 320 เติมสีเทา rgb(114,114,114) แปลงเป็น tensor float32 ลำดับ BGR ไม่ normalise ตามที่ฝึก แล้วรันโมเดล
  7. คะแนนของแต่ละกล่องคือ objectness × คะแนนคลาส กรองคะแนนต่ำกว่า 0.2 ตัดกล่องที่เล็กกว่า 4 px แล้วทำ NMS ข้ามคลาสที่ IoU 0.6
  8. ผลกลับมาที่หน้าเว็บ กรองด้วยคะแนนขั้นต่ำของการนับ (0.5) วาดกรอบ (ถ้าเปิดไว้) และป้ายตัวเลข "ปลาในภาพ" พร้อมจำนวนภาพที่นับแล้ว
  9. รอบถัดไปเริ่มทันที ตัวนับ rounds, openMs, countMs อัปเดต และทุก 15 วินาทีส่ง event auto ชนิด beat

7.2 ลำดับการโหลด Load sequence

  1. อ่าน parts.json หนึ่งครั้ง (models.js:33, 66) ชื่อโมเดลถูกตัดสินจาก ?det= หรือค่าตามโหมด
  2. ดาวน์โหลดแต่ละส่วนขนานกัน (fetch ของ <url>.partN) คัดลอกลง Uint8Array ที่ตำแหน่ง i × 20 MiB แล้วตรวจขนาด
  3. สร้าง session ด้วย sessionFrom: ลอง webgpu ก่อนแล้วจึง wasm ตัวแรกที่สำเร็จชนะ ข้าม webgpu ถ้าไม่มี navigator.gpu และ ?ep=wasm บังคับให้ใช้ CPU
  4. อ่านขนาดอินพุตจากโมเดล (ค่าสำรอง 432 สำหรับตัวตรวจจับแบบ RF-DETR)
  5. โหมดนับไม่โหลด embedder เว้นแต่ id=1 ซึ่งโหลด embed บน wasm (เว้นแต่ ?embEp=webgpu)
  6. embedTag คือ sha: ตามด้วย 16 hex แรกของ SHA-256 บนตัวอย่าง 16 จุด จุดละ 64 KB รวมความยาว ใช้ตรวจว่าคลังตัวอย่างยังเข้ากับโมเดลเดิม
  7. warm() รันอินพุตศูนย์หนึ่งครั้งห่างจากพร้อมใช้งาน 5 วินาที และไม่รันระหว่างการนับ

7.3 การเลือก EP และเธรด Execution providers and threads

  • EP ลำดับคือ WebGPU ก่อนแล้ว wasm ค่าที่ไม่รู้จักในรีโพใช้ได้เฉพาะ wasm
  • จำนวนเธรดคือ 1 เมื่อหน้าไม่ได้ cross-origin isolated หรือเป็นโหมด LEAN ที่มี WebGPU ไม่เช่นนั้นใช้ min(4, จำนวนคอร์) เธรดของ wasm ต้องการ COOP/COEP
  • COOP/COEP ตั้งโดย sw.js และโดย dist/_headers ถ้าหน้ายังไม่ isolated ทั้งที่มี controller หน้าจะโหลดซ้ำหนึ่งครั้ง (sessionStorage coi)
  • เวิร์กเกอร์เป็น module worker เมื่อมี Worker และ OffscreenCanvas ไม่เช่นนั้นรันในหน้าเว็บ ?noworker บังคับให้รันในหน้าเว็บ

PWA (Progressive Web App)เว็บแอปที่ติดตั้งและทำงานออฟไลน์ได้ ใช้ service worker และ manifest.webmanifest
YOLOX-tinyโมเดลตรวจจับวัตถุแบบ one-stage ขนาดเล็ก ใช้ในโหมดนับ อินพุต 320 px ใบอนุญาต Apache-2.0
Object detector (ตัวตรวจจับ)โมเดลที่หาตำแหน่งและคะแนนของวัตถุในภาพ ให้กรอบและคลาส
Bounding box (กรอบ)สี่เหลี่ยมที่ครอบวัตถุ เก็บเป็น cx, cy, w, h ในโค้ด
Objectnessคะแนนว่ามีวัตถุอยู่หรือไม่ของ YOLOX ก่อนคูณด้วยคะแนนคลาส
Letterbox (เลตเตอร์บ็อกซ์)ย่อภาพให้พอดีกรอบจัตุรัสโดยรักษาสัดส่วน และเติมขอบ (ที่นี่เติมสีเทา 114)
NMS (Non-Maximum Suppression)ตัดกล่องซ้ำซ้อนให้เหลือกล่องที่คะแนนสูงสุด ที่นี่ใช้ IoU 0.6 ข้ามคลาส
IoU (Intersection over Union)อัตราส่วนพื้นที่ทับซ้อนต่อพื้นที่รวมของสองกล่อง ใช้จับคู่และใช้ใน NMS
ONNXรูปแบบโมเดลมาตรฐานเปิด ไฟล์นามสกุล .onnx
ONNX Runtime Web (ORT)เอนจินรันโมเดล ONNX ในเบราว์เซอร์ ไฟล์อยู่ใน app/vendor
WebGPUAPI ประมวลผลบน GPU ของเบราว์เซอร์ ใช้เป็น EP แรก
wasm (WebAssembly)รูปแบบโค้ดที่รันในเบราว์เซอร์บน CPU ใช้เป็นตัวสำรอง
EP (Execution Provider)แบ็กเอนด์ที่ ONNX Runtime ใช้รันโมเดล เช่น webgpu หรือ wasm
Worker (Web Worker)เธรดแยกของเบราว์เซอร์ ที่นี่ใช้รันโมเดลเพื่อไม่ให้หน้าจอค้าง
Service workerสคริปต์ที่ทำงานเบื้องหลังของเบราว์เซอร์ แคชไฟล์และดักคำขอ fetch
COOP / COEPheader ที่ทำให้หน้าเป็น cross-origin isolated ซึ่งเธรดของ wasm ต้องใช้
ImageBitmapภาพที่โอนความเป็นเจ้าของได้ (transferable) ส่งเข้าเวิร์กเกอร์โดยไม่คัดลอก
OffscreenCanvascanvas ที่วาดได้นอกหน้าจอหรือในเวิร์กเกอร์ และแปลงเป็น bitmap ได้
requestVideoFrameCallback (rVFC)callback ที่เรียกเมื่อวิดีโอมีเฟรมใหม่ ใช้ในลูปสดและในการรอเฟรม
UAT (User Acceptance Test)การทดสอบยอมรับจากผู้ใช้หรือเจ้าของระบบ ทำหลัง deploy บน production แบบอ่านอย่างเดียว
Embedder (ตัวฝังข้อมูล)โมเดลที่แปลงภาพปลาเป็นเวกเตอร์ตัวเลขเพื่อเทียบว่าเป็นตัวเดียวกันหรือไม่
Re-ID (re-identification)การระบุตัวตนซ้ำของวัตถุเดิมจากภาพใหม่
JDE (Joint Detection and Embedding)แนวทางรวมการตรวจจับและการสร้างเวกเตอร์ไว้ในเครือข่ายเดียว (ตัวเลือกในแผน)
FairMOTโมเดลติดตามหลายวัตถุที่รวมการตรวจจับกับ re-ID (ตัวเลือกในแผน)
ByteTrack-liteตัวติดตามแบบเรียบง่ายที่จับคู่กรอบสองขั้นด้วย IoU
Hungarian algorithmการจับคู่แบบดีที่สุดระหว่างสองชุด ใช้ในตัวติดตาม
Follow (follow.js)การเลื่อนกรอบให้ตามปลาระหว่างรอบตรวจจับ
embedTagลายนิ้วมือของโมเดลที่ใช้สร้างเวกเตอร์ ใช้ตรวจว่าคลังตัวอย่างยังเข้ากับโมเดลเดิม
Gallery (คลังปลา)ชุดตัวอย่างปลาของบ่อหนึ่งบ่อ พร้อมหมายเลขและชื่อ
Pond (บ่อ)หน่วยของคลัง ระบุด้วย id และพิกัด
Exemplar (ตัวอย่างอ้างอิง)ภาพหรือเวกเตอร์ของปลาหนึ่งตัวที่ใช้เทียบ
Colour mask (มาสก์สี)มาสก์ที่แยกลำตัวปลาจากน้ำด้วยสี ใช้ครอปในโหมด id
D1ฐานข้อมูล SQLite ของ Cloudflare
R2พื้นที่เก็บไฟล์ของ Cloudflare ระบบนี้ยกเลิกการใช้เมื่อ 30 ต.ค. 2026
Pages Functionsฟังก์ชันเซิร์ฟเวอร์ของ Cloudflare Pages ที่นี่อยู่ใน functions/api
Compare-and-swap (CAS)เขียนได้เมื่อเวอร์ชันที่อ่านมาตรงกับเวอร์ชันปัจจุบัน ใช้กับ ver ของบ่อ
Bearer tokenโทเคนในหัว Authorization ของคำขอ API
Evalการประเมินการนับกับคลิปที่ติดป้ายแล้ว ผ่าน eval_app.py
Strideระยะก้าวของการประมวลผลในการ eval หน่วยเป็น 1/30 วินาที
Footprintค่าหน่วยความจำของโปรเซสตามที่ macOS รายงาน ใช้วัด WebKit
Safe ladderกลไกกู้ตัวเองที่เพิ่มหรือลดระดับความปลอดภัยตามการตายของรอบก่อน
LEANโหมดเบาสำหรับ iPhone ใช้ koi_det_lite16 และ batch 2
COUNT / IDSโหมดนับ (ค่าเริ่มต้น) และโหมดระบุตัวปลา (id=1)
Field logบันทึกจากอุปกรณ์จริงที่ส่งเข้าตาราง logs ของ D1
Google Colabสภาพแวดล้อมเทรนของ Google ที่เป็นค่าเริ่มต้นของการเทรนและ eval
AGPL (Ultralytics)ใบอนุญาตที่หลีกเลี่ยง เพราะต้องเปิดซอร์สและมีข้อจำกัดเชิงพาณิชย์
Apache-2.0ใบอนุญาตโอเพนซอร์สที่ระบบจะใช้เมื่อเปิดซอร์ส
PDPAกฎหมายคุ้มครองข้อมูลส่วนบุคคลของไทย ใช้เป็นกรอบเรื่องพิกัดและข้อมูลอุปกรณ์
Code pointหน่วยอักขระของ Unicode ใช้นับความยาวชื่อปลา
verเลขเวอร์ชันของคลังบ่อใน D1
autoCount, photoRun, quietชื่อฟังก์ชันและพารามิเตอร์ในโค้ด: วงจรนับ, ประมวลผลภาพหนึ่งภาพ, โหมดไม่ส่ง event รายรอบ
autoKeep, autoGen, photoBusyชื่อตัวแปรในโค้ด: เก็บสตรีมไว้ระหว่างรอบ, เลขรุ่นของวงจรนับ (ใช้หยุดรอบเก่า), ธงกันการประมวลผลซ้อน
