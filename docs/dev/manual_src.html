1Koi ID คืออะไร และสถานะWhat it is and status

Koi ID เป็น PWA ที่นับปลาคาร์ฟ (koi) ในบ่อจากกล้องมือถือ ภาพถ่าย หรือไฟล์วิดีโอ การตรวจจับทำบนเครื่อง (on-device) ด้วยโมเดล YOLOX-tiny ผ่าน ONNX Runtime Web บน WebGPU หรือ wasm โหมดนับจากกล้องส่งเพียง log วินิจฉัย ไม่ส่งภาพออกจากเครื่อง

ระบบนับเฉพาะปลาที่เห็นในเฟรมนั้น ยังไม่ใช่ยอดรวมทั้งบ่อ ซอร์สเปิดภายใต้ Apache-2.0 ที่ github.com/kpanuwat/koi-id-public รีโพสาธารณะเป็นสำเนาที่ส่งออกจากรีโพของผู้ดูแล

โหมด (mode)วิธีเปิด (how to open)สถานะ (status)
นับต่อเนื่องจากกล้อง (continuous camera count) ค่าเริ่มต้น/ แล้วกด กล้องเสถียรบน iPhone
นับจากภาพถ่าย (photo count)/ แล้วกด ถ่ายภาพเสถียร
นับจากไฟล์วิดีโอ (video file count)/ แล้วกด ไฟล์วิดีโอทดลอง
เลขประจำตัวปลาถาวร (permanent fish numbers)/?id=1ทดลอง ไม่เสถียรบน iPhone
แอปเต็ม: ติดตาม ตั้งชื่อ คลังปลา (full app)/?count=0เดสก์ท็อปและ eval เท่านั้น
กล้องสดแบบ realtime (live camera)/?live=1ไม่เสถียร

เสถียร ใช้งานได้จริงบนโทรศัพท์ · ทดลอง ยังไม่ยืนยันบน iPhone · ไม่เสถียร ตายบน iPhone ในการทดสอบ · เดสก์ท็อป ใช้กับเครื่องพัฒนาและ eval

2Quick StartInstall, run, and test on one page

ต้องมี: Node.js 22 หรือ 24 (ใช้ npx) · git · Chrome หรือ Edge บนเดสก์ท็อป (รองรับ WebGPU) · Python 3.12 เฉพาะเมื่อจะใช้โฟลเดอร์ train/
  1. โคลนรีโพแล้วเข้าโฟลเดอร์ 
    git clone https://github.com/kpanuwat/koi-id-public koi-id
cd koi-id
  2. ดึงไฟล์ส่วนของโมเดล (model parts) จาก GitHub Release ลงใน app/models/ 
    scripts/fetch_models.sh
  3. เปิดเซิร์ฟเวอร์ local (ปล่อยไว้ เปิดเทอร์มินัลใหม่สำหรับขั้นถัดไป) 
    cd app && npx --yes http-server@14.1.1 -p 8766 -a 127.0.0.1 -c-1 -s
  4. เปิด http://127.0.0.1:8766/ ใน Chrome หรือ Edge กด กล้อง เพื่อนับต่อเนื่อง หรือ ถ่ายภาพ เพื่อนับหนึ่งภาพ
  5. ก่อนแก้โมดูล ตรวจไวยากรณ์ด้วยสำเนา .mjs ที่รากรีโพ 
    cp app/app.js /tmp/app.mjs && node --check /tmp/app.mjs
  6. (ไม่บังคับ) ทดสอบ API แบบ local ด้วย wrangler pages dev ชั่วคราว 
    scripts/api_limits_test.sh
  7. ต้องการ iPhone หรือ URL ของตัวเอง ให้ deploy ไปยัง Cloudflare ของคุณ ดูหัวข้อ 9
  • ระหว่างทดสอบเพิ่ม ?dump=1 ได้ แอปจะไม่เรียก /api เลย
  • Python http.server ไม่รองรับ HTTP Range วิดีโอจึง seek ไม่ได้ ใช้ http-server ตามคำสั่งข้างต้น
  • iPhone (Safari 26 ขึ้นไป) ต้องใช้ HTTPS ซึ่งได้จากการ deploy เท่านั้น

3สถาปัตยกรรมArchitecture

ระบบมีสามชั้น ได้แก่ หน้าเว็บกับเวิร์กเกอร์บนโทรศัพท์ service worker ที่แคชโค้ดและโมเดล และ Cloudflare ที่เสิร์ฟไฟล์นิ่ง รับคำขอ API และเก็บข้อมูลใน D1 ไฟล์โมเดลไม่อยู่ใน repo แต่อยู่ใน GitHub Release

  • หน้าเว็บ (app/app.js) จัด UI กล้อง วงจรนับ และการวาดกรอบ การตรวจจับทำในเวิร์กเกอร์ (worker.js, pipeline.js, models.js) เพื่อไม่ให้หน้าจอค้าง
  • ตัวตรวจจับคือ YOLOX-tiny (koi_yx320) รันด้วย ONNX Runtime Web 1.29.0 บน WebGPU และใช้ wasm เป็นตัวสำรอง โหมดระบุตัวปลาเพิ่ม embed.onnx
  • sw.js แคชโค้ด (CACHE) และโมเดล (MODELS) และใส่ header COOP/COEP
  • backend เป็นทางเลือก ได้แก่ Cloudflare Pages Functions (functions/api/[[path]].js) และ D1 สำหรับ log กับการซิงก์คลังของโหมดเต็ม

4วงจรนับต่อเนื่องContinuous count loop

กดปุ่ม กล้อง ในโหมดนับ ฟังก์ชัน autoCount() ใน app/app.js เปิดกล้องหนึ่งครั้งแล้ววนรอบโดยไม่มีช่วงพัก ผลของรอบก่อนค้างบนจอจนผลรอบใหม่วาดเสร็จ จึงไม่มีจอว่างระหว่างรอบ

  1. รอเฟรมถัดไปจากวิดีโอที่ซ่อนอยู่ แล้วคัดลอกลง OffscreenCanvas ตัวเดียวที่ใช้ซ้ำทุกรอบ สตรีมกล้องเปิดค้างไว้ตลอด (ค่าเริ่มต้น)
  2. บน iPhone จับภาพ 1280x720 (?shotH= เปลี่ยนได้ เดสก์ท็อปใช้ 1080)
  3. photoRun ส่ง ImageBitmap ให้เวิร์กเกอร์ด้วยการโอนความเป็นเจ้าของ (transfer) ถ้ารอบก่อนยังไม่เสร็จ (photoBusy) รอบนั้นจะคืนค่าทันทีโดยไม่ประมวลผล ดูหัวข้อ 10
  4. เวิร์กเกอร์รัน YOLOX แล้วคัดกล่องที่คะแนนต่ำกว่า 0.2 ออก หน้าเว็บนับเฉพาะกล่องที่คะแนนตั้งแต่ 0.5 ขึ้นไป (photoMin) แล้ววาดกรอบและตัวเลข
  5. รอบถัดไปเริ่มทันที ทุก 15 วินาทีส่ง event auto ชนิด beat

หยุดได้ด้วยการกดปุ่มกล้องอีกครั้ง เมื่อแท็บถูกซ่อน (pagehide) หรือกด Escape

  • ก่อนเปิดกล้อง ระบบปล่อยไฟล์วิดีโอที่เล่นค้างอยู่ก่อน
  • แต่ละรอบเป็นอิสระ ไม่มีการติดตามข้ามรอบ และไม่ใช่ยอดรวมของบ่อ
  • โหมดนับไม่ส่ง event photo รายรอบ ให้ดู event auto แทน
กฎการออกแบบที่ยังใช้: iPhone ฆ่าแท็บเมื่อหน่วยความจำเกินราว 1.25 ถึง 1.5 GB ฟีเจอร์ใหม่ควรต่อบนวงจรรอบนี้ หลีกเลี่ยงการจองภาพขนาดเต็มเฟรมในทุกรอบ และวัดด้วย footprint probe ก่อนอ้างว่าแก้ได้

6โมเดลและการโหลดModels and loading

6.1 โมเดลที่ใช้ Models in use

ไฟล์โมเดลขนาด (ประมาณ)ใช้ในโหมดเผยแพร่ใน Release
koi_yx320.onnx20.2 MB, 1 ส่วนนับ (ค่าเริ่มต้น) YOLOX-tiny อินพุต 320 เอาต์พุต [1, 2100, 6]ใช่
embed.onnx43.8 MB, 3 ส่วนระบุตัวปลา (?id=1) และโหมดเต็ม embedder รันบน wasm ในโหมด idใช่
koi_det_lite16.onnx70.2 MB, 4 ส่วนโหมดเต็มบน iPhone (LEAN)ไม่ ฝึกเองด้วย train/train_detector.py
koi_det.onnx71.8 MB, 4 ส่วนโหมดเต็มบนเดสก์ท็อป ตัวตรวจจับแบบ RF-DETR ให้มาสก์ไม่ ฝึกเองด้วย train/train_detector.py

ไฟล์ .onnx แบ่งเป็นส่วน .onnx.partN ไม่เกิน 20 MiB (20,971,520 bytes) เพราะ Cloudflare Pages จำกัดขนาดไฟล์ รายการอยู่ใน app/models/parts.json ที่ train/split_models.py เขียน

  • koi_yx320: letterbox เป็น 320x320 เติมสีเทา 114 แปลงเป็น float32 ช่องสีเรียงแบบ BGR ไม่ normalise ตามที่ฝึก
  • การคัดกล่อง: คะแนนของกล่อง = objectness คูณคะแนนคลาส กรองคะแนนต่ำกว่า 0.2 ตัดกล่องที่เล็กกว่า 4 px แล้วทำ NMS ข้ามคลาสที่ IoU 0.6

6.2 ลำดับการโหลด Load sequence

  1. อ่าน parts.json แล้วเลือกโมเดลจาก ?det= หรือค่าตามโหมด
  2. ดาวน์โหลดทุกส่วนพร้อมกัน ต่อเข้า buffer แล้วตรวจขนาด
  3. สร้าง session โดยลอง webgpu ก่อน ถ้าไม่ได้ใช้ wasm (?ep=wasm บังคับ CPU)
  4. โหมดนับไม่โหลด embedder เว้นแต่ id=1
  5. warm() รันอินพุตศูนย์หนึ่งครั้งห่างจากพร้อมใช้งาน 5 วินาที และไม่รันระหว่างการนับ

เธรดของ wasm ต้องใช้ COOP/COEP ซึ่ง sw.js และ _headers บน Pages ตั้งให้ ถ้าหน้ายังไม่ isolated ทั้งที่มี controller หน้าจะโหลดซ้ำหนึ่งครั้ง

6.3 แคชของ service worker Service worker caches

แคชเก็บอะไรวิธีอ่าน
CACHE (koi-id-*)โค้ดและ shell เช่น index.html, app.jsnetwork first ถ้าไม่ได้จึงใช้แคช
MODELS (koi-models-*).onnx, .wasm และ .partN deploy.sh เป็นผู้เขียนค่าcache first ไม่สนใจ query string
koi-last-videoวิดีโอล่าสุดเพื่อเล่นต่อ (ไม่เกิน 30 MB บน iOS และ 300 MB บนแพลตฟอร์มอื่น)activate ไม่ลบ

activate ลบแคชอื่นที่ไม่อยู่ในรายการ fetch ข้ามคำขอที่ไม่ใช่ GET, cross-origin, Range และ /api/ ค่า MODELS มาจาก sha1 ของส่วนโมเดลและ wasm (12 ตัวแรก)

6.4 วิธีเพิ่มโมเดลใหม่ How to add a model

  1. ส่งออกไฟล์ .onnx จาก train/ หรือ Colab แล้วเก็บไว้นอกโฟลเดอร์ที่ deploy (ไฟล์เต็มไม่ถูก deploy)
  2. รัน train/split_models.py เพื่อเขียน app/models/<ชื่อ>.onnx.partN และอัปเดต parts.json
  3. เพิ่มการเลือกโมเดลใน app/models.js ตามโหมดหรือ ?det= แล้วตรวจขนาดอินพุตจากไฟล์จริง
  4. commit ส่วนโมเดลและ app/sw.js ถ้า deploy.sh หยุดด้วยรหัสออก 1 หมายความว่าแฮชเปลี่ยนและ sw.js ถูกเขียนใหม่ ให้ commit แล้วรันอีกครั้ง
  5. ถ้าจะเผยแพร่ให้ผู้อื่นโหลด อัปโหลดเป็น GitHub Release ใหม่ แล้วแก้ tag ใน scripts/fetch_models.sh และ bump BUILD กับ CACHE ตามหัวข้อ 9

follow, followHz, followMask, followVF, followGlideเปิด, 15 Hz บน iOS, 30 อื่นปรับการเลื่อนกรอบของ follow.js
dumpปิด1 ไม่ส่ง log ไม่ลงทะเบียนอุปกรณ์ ไม่เรียก /api (eval และทดสอบ)
noworkerปิดรันไปป์ไลน์บนเธรดหน้าเว็บ (debug)
stride, max1, ไม่จำกัดก้าววิดีโอทีละ stride/30 วินาที และหยุดหลัง N เฟรม (eval)

8ระบบหลังบ้านBackend: API, D1, logs

API อยู่ที่ /api/* ในไฟล์เดียว functions/api/[[path]].js ทุกคำขอตรวจโทเคนก่อน ยกเว้น enroll เกินโควตาได้ 429 ข้อมูลใหญ่เกินได้ 413 ข้อผิดพลาดภายในไม่ส่ง SQL กลับ เส้นทางที่ไม่รู้จักตอบ 404

8.1 เส้นทาง API Routes

วิธีเส้นทางสิทธิ์ทำอะไรขีดจำกัด
POST/api/enrollไม่ต้องมีโทเคนลงทะเบียนอุปกรณ์ เก็บเฉพาะแฮชของโทเคน ได้โทเคน d.<id>.<secret>10 อุปกรณ์ใหม่ต่อ IP hash ต่อวัน 300 ทั้งระบบ body 1 KB
GET/api/pingอุปกรณ์หรือผู้ดูแลตรวจว่าโทเคนใช้ได้-
PUT/api/blob/<part>?key=&type=ผู้ดูแลเท่านั้นเขียนบล็อบ key ต้องขึ้นต้นด้วย ponds/<id>/1 MB ต่อส่วน
POST/api/logอุปกรณ์หรือผู้ดูแลเพิ่มแถวในตาราง logsbody 4 KB, 1,000 แถวต่ออุปกรณ์ต่อวัน
GET/api/meอุปกรณ์หรือผู้ดูแลตอบจำนวนวันที่ใช้งาน (days) และ admin-
GET/api/pondsอุปกรณ์หรือผู้ดูแลรายการบ่อ (id, name, lat, lon, fish, updated_at, merged_into) ทุกอุปกรณ์เห็นทุกบ่อ-
GET/api/pond/<id>?since=อุปกรณ์หรือผู้ดูแลข้อมูลบ่อและคลังปลา ถ้า since ตรงกับ ver จะได้ gallery เป็น null-
PUT/api/pond/<id>อุปกรณ์หรือผู้ดูแล มีกติกาเพิ่มบันทึกคลังแบบ compare-and-swap nextFish ห้ามลดหรือกระโดดเกิน +1000 ชื่อและพิกัดตั้งได้ครั้งเดียว1,500 ต่อวัน 300 ต่อชั่วโมง
POST/api/pond/<id>/mergeอุปกรณ์หรือผู้ดูแลตั้ง merged_into ให้บ่อ ตอบ 409 ถ้าปลายทางไม่มีหรือถูกรวมไปแล้ว10 ครั้งต่ออุปกรณ์ต่อวัน
POST/api/sampleอุปกรณ์หรือผู้ดูแลตัวอย่างปลา (meta JSON และภาพ) แก้ได้เฉพาะของตัวเอง3,000 ชิ้นและ 100 MB ต่ออุปกรณ์ต่อวัน ภาพ 2 MB
POST/api/frameอุปกรณ์หรือผู้ดูแลเฟรมและผลตรวจจับ (dets)300 เฟรมและ 150 MB ต่ออุปกรณ์ต่อวัน ภาพ 2 MB dets 256 KB

8.2 การยืนยันตัวตน Authentication

  • โทเคนผู้ดูแล (admin): เท่ากับความลับ SYNC_TOKEN เทียบแบบ constant-time ใช้กับเครื่องมือเท่านั้น ห้ามอยู่ในเบราว์เซอร์และห้าม commit
  • โทเคนอุปกรณ์: รูปแบบ d.<id>.<secret> เซิร์ฟเวอร์เก็บเฉพาะแฮช SHA-256 ใน devices.token_hash เบราว์เซอร์เก็บที่ koi.deviceToken
  • days: จำนวนวัน UTC ที่อุปกรณ์เคยใช้งาน ใช้เป็นเงื่อนไขของเกรดและการลบปลา

9.2 Deploy ของตัวเอง Deploy your own instance

ต้องมีบัญชี Cloudflare (free tier พอ) หลังสร้างฐาน D1 ให้ใส่ database_id ที่ได้ลงใน wrangler.toml ก่อนรันขั้น migrations

npx wrangler@4 login
npx wrangler@4 d1 create koi-id
for f in migrations/*.sql; do npx wrangler@4 d1 execute koi-id --remote --file "$f"; done
npx wrangler@4 pages project create koi-id --production-branch main
openssl rand -hex 24 | npx wrangler@4 pages secret put SYNC_TOKEN --project-name koi-id
KOI_PROJECT=koi-id ./deploy.sh
  • ใช้ d1 execute ทีละไฟล์ตามตัวอย่าง ไม่ใช้ migrations apply --remote
  • SYNC_TOKEN คือโทเคนผู้ดูแล เก็บเป็นความลับ บน CI หรือเซิร์ฟเวอร์ที่ไม่มี OAuth ให้ตั้ง CLOUDFLARE_API_TOKEN และ CLOUDFLARE_ACCOUNT_ID แทน
  • ไม่มี backend ก็ใช้แอปได้ โหมดนับทำงานในเครื่องทั้งหมด คำขอ /api/* จะล้มและถูกเพิกเฉย

10กฎและข้อควรระวังRules and pitfalls

  1. ห้ามวางโค้ดต่อหลังคอมเมนต์ // ในบรรทัดเดียวกัน คำสั่งจะหายไปโดยไม่มี error เขียนคอมเมนต์เป็นบรรทัดของตัวเอง
  2. node --check ใช้ได้เฉพาะกับสำเนา .mjs ไม่ใช่ไฟล์ .js ตรง ๆ
  3. ห้ามส่งข้อมูลทดสอบหรือคำสั่งเขียนไปยัง production ทดสอบกับ local เท่านั้น
  4. bump BUILD และ CACHE ทุกครั้งที่ deploy และห้ามแก้ MODELS ด้วยมือ ไม่เช่นนั้น service worker อาจไม่ดึงโค้ดใหม่ และ safe ladder จะไม่รีเซ็ต
  5. หมายเลขปลาไม่ถูกนำกลับมาใช้ เซิร์ฟเวอร์ปฏิเสธคลังที่ nextFish ลดลง (409)
  6. iPhone ฆ่าแท็บเมื่อหน่วยความจำเกินราว 1.25 ถึง 1.5 GB ก่อนอ้างว่าแก้ได้ต้องวัดด้วย footprint probe (หัวข้อ 4)
  7. Pages ไม่รองรับ HTTP Range สำหรับวิดีโอ การ seek อาจล้มเหลว ทดสอบ seek บน local ก่อน
  8. CDN อาจส่งโค้ดเก่าได้ราว 1 นาทีหลัง deploy รอแล้วทดสอบใหม่
  9. VM Linux แบบ arm64 ไม่มี WebGPU จึงรันเป็น wasm ซึ่งช้ามาก ทดสอบที่ต้องใช้ WebGPU บน Mac หรือเดสก์ท็อปที่มี Chrome หรือ Edge
  10. log ต้องมี body ไม่เกิน 4 KB และไม่เกิน 41 รายการต่อการโหลดหน้า เกินจะถูกทิ้งเงียบ ๆ จึงใช้ event แบบ beat แทนรายรอบ
  11. deploy.sh อัปโหลดไฟล์ที่ยังไม่ commit ไปด้วย (--commit-dirty=true) ให้ commit ก่อนรัน
  12. รีโพสาธารณะเป็น mirror PR ที่รับแล้วจะถูกนำกลับเข้ารีโพของผู้ดูแล แล้วส่งออกใหม่ ไม่ได้ deploy จากรีโพสาธารณะโดยตรง

NMS (Non-Maximum Suppression)ตัดกล่องซ้ำซ้อนให้เหลือกล่องคะแนนสูงสุด ที่นี่ใช้ IoU 0.6 ข้ามคลาส
IoU (Intersection over Union)อัตราส่วนพื้นที่ทับซ้อนต่อพื้นที่รวมของสองกล่อง
ONNXรูปแบบโมเดลมาตรฐานเปิด นามสกุล .onnx
ONNX Runtime Web (ORT)เอนจินรันโมเดล ONNX ในเบราว์เซอร์ ไฟล์อยู่ใน app/vendor/
WebGPUAPI ประมวลผลบน GPU ของเบราว์เซอร์ ใช้เป็น EP แรก
wasm (WebAssembly)รูปแบบโค้ดที่รันบน CPU ในเบราว์เซอร์ ใช้เป็นตัวสำรอง
EP (Execution Provider)แบ็กเอนด์ที่ ONNX Runtime ใช้รันโมเดล เช่น webgpu หรือ wasm
Web Workerเธรดแยกของเบราว์เซอร์ ที่นี่ใช้รันโมเดลเพื่อไม่ให้หน้าจอค้าง
COOP / COEPheader ที่ทำให้หน้าเป็น cross-origin isolated ซึ่งเธรดของ wasm ต้องใช้
ImageBitmapภาพที่โอนความเป็นเจ้าของได้ (transferable) ส่งเข้าเวิร์กเกอร์โดยไม่คัดลอก
OffscreenCanvascanvas ที่วาดได้นอกหน้าจอหรือในเวิร์กเกอร์ และแปลงเป็น bitmap ได้
Embedder (ตัวฝังข้อมูล)โมเดลที่แปลงภาพปลาเป็นเวกเตอร์ตัวเลขเพื่อเทียบว่าเป็นตัวเดียวกันหรือไม่
Re-ID (re-identification)การระบุตัวตนซ้ำของวัตถุเดิมจากภาพใหม่
JDE (Joint Detection and Embedding)แนวทางรวมการตรวจจับกับการสร้างเวกเตอร์ไว้ในเครือข่ายเดียว (ตัวเลือกในแผน)
Gallery (คลังปลา)ชุดตัวอย่างปลาของหนึ่งบ่อ พร้อมหมายเลขและชื่อ
Pond (บ่อ)หน่วยของคลัง ระบุด้วย id และพิกัด
D1ฐานข้อมูล SQLite ของ Cloudflare

Compare-and-swap (CAS)เขียนได้เมื่อเวอร์ชันที่อ่านมาตรงกับเวอร์ชันปัจจุบัน ใช้กับ ver ของบ่อ
Quota (โควตา)ขีดจำกัดจำนวนครั้งและขนาดข้อมูลต่ออุปกรณ์ต่อวันใน API เกินแล้วได้ HTTP 429

Safe ladderกลไกกู้ตัวเองที่เพิ่มหรือลดระดับความปลอดภัยตามการตายของรอบก่อน
