1. ภาพรวมOverview

PWA ที่นับปลาคาร์ฟในบ่อ จำตัว และตั้งชื่อเล่นภาษาไทยอัตโนมัติ จากไฟล์วิดีโอหรือกล้องมือถือ ประมวลผลบนเครื่องทั้งหมด (ภาพไม่ถูกส่งไปประมวลผลที่เซิร์ฟเวอร์) ใช้ offline ได้หลังเปิดครั้งแรก และส่งผลการเรียนรู้ขึ้นที่เก็บส่วนกลางเมื่อผู้ใช้ใส่รหัสซิงก์

  • หลักการ: ภาพต้นฉบับไม่ถูกแก้ไข กรอบและป้ายอยู่บน canvas โปร่งใส · ไม่แน่ใจไม่เดา ชื่อขึ้นเมื่อหลักฐานแยกปลาตัวนั้นได้แล้ว · นับเฉพาะปลาในผิวน้ำของบ่อ
  • พึ่งคนน้อยที่สุด: ระบบติดป้าย รวมตัวซ้ำ แยกตัวที่ชนกัน ตั้งชื่อตามสี และพัฒนาโมเดลรอบใหม่ได้เอง คำตอบของผู้ใช้ใช้เพิ่มความแม่น แต่ไม่มีอะไรต้องรอคำตอบ

3. สถาปัตยกรรมSystem architecture

เส้นประ: โมเดลใหม่ที่ผ่านด่านถูก deploy กลับไปที่ Pages แล้วทุกเครื่องได้เมื่อเปิดแอปครั้งถัดไป (คลังปลาถูกย้ายให้อัตโนมัติ ชื่อเดิมอยู่ครบ)

4. แต่ละรอบตรวจจับทำอะไรPer detector pass

  1. จับภาพ เฟรมปัจจุบันเป็น ImageBitmap ส่งเข้า worker (ภาพต้นฉบับไม่ถูกแก้)
  2. ตรวจจับ ปลาและผิวน้ำ ตัดปลานอกบ่อ ทำ NMS (models.js detect)
  3. ติดตาม ByteTrack-lite + ชดเชยกล้องส่าย, track ที่หายไปลืมหลัง 2.5 วินาที หรือ 45 รอบ (tracker.js)
  4. นับ เห็นซ้ำ 3 รอบ, ไม่นิ่งเหมือนหิน, พื้นที่ไม่กระพริบเหมือนแสง (เกณฑ์ 0.45 เครื่องเร็ว / 0.55 เครื่องช้า), ค่ากลาง 5 รอบ
  5. จำหน้า track ที่ถึงเวลา (ทุก 0.27 วินาที ไม่เกิน 6 ตัวต่อรอบ) ได้ crop มาตรฐาน (หัวขวา แกนตัวแนวนอน) แล้ว embedding, ตัดแสงสะท้อน
  6. ระบุตัว Hungarian ทั้งเฟรม, โหวตต่อ track, red flags, ตั้งชื่อ (reid.js step)
  7. วาด ทุกเฟรมวิดีโอ: กรอบและป้ายไหลเข้าหาเป้าหมาย 0.15 วินาที, สีตัวอักษรขาว/ดำตามภาพ

ค่าที่ขึ้นกับเวลาถูกนับเป็นวินาที ไม่ใช่จำนวนรอบ เพราะมือถือทำได้ราว 3 รอบต่อวินาที Mac ราว 6 และการวัดผลแบบทุกเฟรม 30

5. ตัวตน ชื่อ และ flagsIdentity, names, green and red flags

Red flags ระบบแก้เอง

  • ชื่อเดียวกันสองจุดพร้อมกัน: track ที่เข้ากับปลาที่สุดเก็บชื่อ อีก track ถูกบอกว่า "ไม่ใช่ตัวนี้" อาจกลายเป็นปลาหน้าคล้ายตัวใหม่
  • ขนาดต่างจากปลาเกิน 3 sigma: ไม่เรียนรู้มุมใหม่
  • track ที่ชื่อสลับไปมา 2 ครั้ง: ไม่เรียนรู้
  • ภาพจาก track ที่มี red flag ไม่ถูกเก็บเป็นข้อมูลเทรน

Green flags เกรดข้อมูล

  • gold: ผู้ใช้ยืนยันเอง
  • silver: มั่นใจ, ตามได้ 2 วินาทีขึ้นไป, 3 มุมขึ้นไป, แยกจากตัวคล้ายได้
  • bronze: มั่นใจอย่างเดียว หรือระบบติดป้ายเองภายหลัง
  • ปลาที่เห็นพร้อมกันจะไม่ถูกรวมเป็นตัวเดียวกันตลอดไป

ชื่อเล่น

  • ภาษาไทยตามสีและสายพันธุ์, ไม่เกิน 10 ตัวอักษร, ไม่ซ้ำ, ไม่มีตัวเลข (ราว 2,000 ชื่อ)
  • ชื่ออัตโนมัติเปลี่ยนตามสีเมื่อสีนิ่ง ชื่อที่ผู้ใช้ตั้งไม่เปลี่ยนและรอดการรวมตัว
  • ปลาที่ข้อมูลยังไม่พอ: รหัสฐาน 16 สองหลักแบบสุ่ม ชั่วคราว

7. ซ่อมตัวเองและพัฒนาตัวเองSelf-healing and self-evolution

ระหว่างใช้งาน (ในเครื่อง)

  • เพิ่มมุมใหม่ สี และขนาด ให้ปลาที่มั่นใจ
  • รวมตัวซ้ำทุก 30 วินาที (ไม่รวมตัวที่เคยเห็นพร้อมกัน)
  • red flags แยกตัวที่ชนกันเอง
  • ภาพที่ยังไม่แน่ใจ ระบบติดป้ายเองเมื่อคลังรู้จักพอ ไม่ต้องรอผู้ใช้ ค้างเกิน 7 วันทิ้ง
  • ตัวประมวลผลล่ม: สลับไปทำงานในหน้า · แท็บถูกพัก: เล่นต่อเอง · ภาพซ้อนบนจอ: ไม่ติดป้าย

รอบพัฒนา (auto_evolve.sh)

  • เริ่มเมื่อมีภาพคัดแล้วใหม่ตั้งแต่ 200 ภาพ
  • เทรนตัวจำหน้าจากคลิปทดสอบ + ข้อมูลส่วนกลาง (ปลาที่เคยเห็นพร้อมกันในบ่อเดียวกัน = คนละตัว)
  • ด่าน: ชื่อซ้ำ ≤ 2%, ระบุชื่อไม่ต่ำกว่าเดิมเกิน 3 จุด, นับไม่ต่ำกว่าเดิมเกิน 1, ไม่มี error ทุก stride
  • ผ่าน: deploy เอง · ไม่ผ่าน: ใช้โมเดลเดิม บันทึกใน train/runs/evolve/

11. กับดักที่ควรรู้Traps for the next developer

  • วัดผลแบบทุกเฟรมอย่างเดียวไม่พอ ต้องวัด stride 5 และ 10 ด้วยทุกครั้ง
  • ONNX Runtime Web รันสองโมเดลพร้อมกันไม่ได้ (memory access out of bounds) ให้ผ่าน engine.call เสมอ
  • อย่าแก้ไฟล์ใน app/ ระหว่าง eval กำลังโหลดหน้า (คลิป B จะโหลดโค้ดใหม่กลางทาง)
  • python http.server ไม่รองรับ Range: การเลื่อนทีละเฟรมค้างที่ 0
  • fp16: เก็บ GridSample / TopK / Resize / LayerNorm / Softmax เป็น fp32 · embedder ต้อง bake position embedding (WebGPU bicubic Resize พัง)
  • เปลี่ยน embedder แล้วคลังต้องย้าย: แอปทำเองจากภาพในเครื่อง ชื่ออยู่ครบ
  • เลขปลาเริ่มที่ 1 ในทุกบ่อ: การรวม ลบ คัดภาพ ต้องกรองตามบ่อ
  • zsh ไม่แยกคำใน $var: ใช้ function ที่รับ argument ชัดเจน
  • เทรนบน Mac 16 GB: batch 1, จำกัดหน่วยความจำ MPS, ครอบด้วย caffeinate
